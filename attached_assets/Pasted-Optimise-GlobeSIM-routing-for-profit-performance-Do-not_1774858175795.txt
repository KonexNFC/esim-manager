Optimise GlobeSIM routing for profit + performance.

Do not rebuild the existing provider registry, normalized plans, routing engine, pricing engine, checkout flow, or admin panel.
Improve the current routing layer in place.

PRIMARY GOAL
Make provider selection smarter so GlobeSIM maximises:
1. gross margin
2. fulfilment success rate
3. speed / reliability
4. destination-specific performance
5. fallback quality

The engine should stop acting like a simple selector and start acting like a true optimisation system.

- provider cost

- recent success rate
- recent latency
- destination performance
- failover quality
- manual rules / exclusions

- ranked provider list
- fallback chain

- confidence score

3. ADD WEIGHTED PROFITABILITY STRATEGY
==================================================

Create a new routing strategy:
profit_performance_optimized

This should score providers using a weighted combination of:
- projected gross margin
- success rate
- latency
- destination win rate
- failover risk
- health score

Suggested default weights:
- projected margin: 35
- success rate: 25
- destination performance: 15
- health score: 10

==================================================
4. ADD CONFIDENCE SCORING
==================================================

Each routing decision should return a confidence score 0–100.

Examples:
- 95 = strong choice, healthy provider, strong destination history, high margin
- 62 = acceptable but weaker confidence
- 40 = risky choice, limited data or degraded provider

If confidence is low:
- prefer safer provider if margin difference is small
- surface a warning in admin

==================================================
5. ADD MARGIN PROTECTION LOGIC
==================================================

Protect the business from weak-routing decisions.

Rules:
- do not auto-select offers below minimum margin unless no better option exists
- if margin difference between providers is small, prefer higher success provider
- if health is degraded, margin alone should not win
- if provider has repeated recent failures, exclude temporarily

Add configurable thresholds:
- minimum acceptable margin %
- minimum health score
- maximum acceptable recent failure rate
- maximum acceptable latency

==================================================
6. ADD SMART FAILOVER QUALITY SCORING
==================================================

Not all primary selections are equal.
A provider with strong fallback options may be better than one with no good backup path.

Create fallback quality score using:
- number of valid fallback providers
- average fallback health
- average fallback margin
- expected fallback success rate

Use this in optimisation scoring.

If UAE 5GB plans should remain around a target band, do not push markup beyond acceptable threshold.
