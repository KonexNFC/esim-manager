Build the Stripe + provider integration layer for GlobeSIM.

IMPORTANT
Do not rebuild the landing page or dashboard UI from scratch.
Keep the current GlobeSIM frontend, customer login, dashboard, eSIM cards, and top-up UI intact.
This task is to add the backend commerce and provider integration architecture so GlobeSIM becomes a real transactional product.

PRIMARY OBJECTIVE
Turn GlobeSIM into a working eSIM commerce platform with:
1. live Stripe payment flow
2. order creation
3. post-payment fulfillment hooks
4. provider API abstraction
5. usage sync
6. top-up processing
7. lifecycle automation readiness

PRODUCT REQUIREMENTS
After implementation, GlobeSIM should support this flow:

A. Customer selects a plan
B. Customer checks out via Stripe
C. On successful payment, system creates/links customer account
D. System creates order record
E. System calls provider integration layer to provision or assign eSIM
F. Purchased eSIM appears in customer dashboard
G. Customer can later view usage and top up
H. System can sync provider status/usage periodically

==================================================
4. WEBHOOK HANDLING
==================================================

Implement a secure Stripe webhook endpoint.

Handle at minimum:
- checkout.session.completed
- payment_intent.succeeded
- payment_intent.payment_failed
- charge.refunded
- customer.created if useful
- payment_method.attached if used later

Webhook responsibilities:
- verify Stripe signature
- create/update order
- create or link user account
- trigger fulfillment
- trigger email notifications
- update dashboard data
- handle idempotency properly

Critical:
Webhook processing must be idempotent.
Do not create duplicate orders or duplicate eSIM assignments if Stripe retries events.
